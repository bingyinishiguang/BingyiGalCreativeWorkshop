LIBRARY

立绘库清理

—

导入立绘的顺序是「先把图片写进硬盘，再往库里记一笔」。如果正好卡在中间（程序被杀、断电、蓝屏），硬盘上就会留下图库里不显示、也删不掉的图片文件。批量入库上千张时中断一次，可能留下几百 MB 这种垃圾。

扫描只查看、不删任何东西；确认后才会清理，而且只会删立绘库目录里的文件。

还没扫描。点「扫描未入库文件」看看有没有垃圾。

▣
DATA

数据位置

—

立绘库、设置、导出等用户数据的存放位置。开发态固定为项目「工作数据」；安装版默认在系统 AppData。

✓
CHECK

运行体检

—

一次检查"能不能正常用"的前提：素材包形态、数据目录可写、三适配器、取用精灵与拖放组件、立绘库索引。发反馈时把结果一起发来即可定位。

▤
LOGS

日志与诊断包

—

startup.log 里每个请求都有一行「方法 路径 状态 耗时」（窗口几何类细节默认不写，需要时设环境变量 BINGYI_DEBUG=1）。诊断包 = 日志 + 扫描摘要 + 设置 + 统计，不含任何游戏素材，可以直接发回来。

每次启动都会写这一份；超过 1.5 MB 只保留最近 4000 行。

把日志、扫描摘要、设置与统计打成一个 zip（不含任何游戏素材）
